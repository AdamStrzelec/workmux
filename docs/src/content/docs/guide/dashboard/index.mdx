When running agents in multiple worktrees across many projects, it's helpful to have a centralized view of what each agent is doing. The dashboard provides a TUI for monitoring agents, reviewing their changes, staging hunks, and sending commands.

:::note[Optional feature]
The dashboard is entirely optional. It becomes especially useful when running multiple agents across several projects, but workmux's core workflow works great on its own.
:::

## Setup

:::caution[Prerequisites]
The dashboard requires [status tracking hooks](/guide/status-tracking/) to be configured. Without them, no agents will appear.
:::

Add this binding to your `~/.tmux.conf`:

```bash
bind C-s display-popup -h 30 -w 100 -E "workmux dashboard"
```

Then press `prefix + Ctrl-s` to open the dashboard as a tmux popup. Feel free to adjust the keybinding and popup dimensions (`-h` and `-w`) as needed.

:::tip[Quick access]
Consider binding the dashboard to a key you can press without the tmux prefix, such as `Cmd+E` or `Ctrl+E` in your terminal emulator. This makes it easy to check on your agents at any time.
:::

See [command reference](/reference/commands/dashboard/) for CLI options.

## Views

The dashboard has two views, toggled with `Tab`:

- **Agents**: Shows all running agent panes with their status, git info, GitHub branch checks, and live terminal preview
- **Worktrees**: Shows all git worktrees with branch, PR status, GitHub branch checks, and agent summary. Press `r` to remove a worktree (kills agent, removes worktree, deletes branch).

### PR actions menu

Press `p` on a worktree to open the PR actions menu. Every action shows the
commands it will run and waits for `y` before running them in the background.
Entries that cannot run are dimmed with a short reason (no `gh`, no PR, PR not
open, draft, conflicts, failing CI, PRs still loading).

| Key       | Action                                                                     |
| --------- | -------------------------------------------------------------------------- |
| `p`       | Push the branch (`git push -u origin`, no force); create a draft PR if none is open |
| `d`       | Toggle the PR between draft and ready for review                           |
| `m`       | Merge the PR (`gh pr merge --merge`)                                       |
| `M`       | Merge the PR, then remove the worktree and local branch                    |
| `c`       | Close the PR without merging                                               |
| `h`/`Esc` | Back                                                                       |

New PRs target the worktree's base branch (set with `b`), or the default branch.

### Run tools menu

Press `x` on a worktree to list the [`tools`](/guide/configuration/#run-tools)
of the project by key. Pressing a tool's key runs its command in a new tmux
window named `<prefix><worktree>/<tool name>` with the worktree as working
directory (inside the worktree's own session in session mode, else in the
session the dashboard was started from). If that window is already open the
dashboard switches to it instead of starting a second copy; running tools are
marked in the menu. `Esc` closes the menu.

`c` also closes the worktree's tool windows (disable with
`tools.close_with_session: false`), and `r` always kills them before removing
the worktree.

### Claude session resume

When `c` closes a worktree window whose agent is Claude, the dashboard saves
that agent's session id (from the status hooks, else the newest transcript for
the worktree) in the worktree metadata. The next open of that worktree
(`Enter`, `workmux open`) starts Claude with `--resume <id>` if the transcript
still exists, and a fresh session otherwise. The saved id is used once.
Disable with `claude.resume_on_reopen: false`.

### Project config

Press `C` to edit the project's `.workmux.yaml`: session tabs and the
worktree directory (Layout page), run tools (Tools page) and Claude launch
settings (Claude page). `Tab` switches pages. Opening the editor never writes anything; `s` saves. Only
the changed keys are rewritten, other lines and comments are kept.

Press `w` to edit the worktree directory ([`worktree_dir`](/guide/configuration/)).
The **Current** line shows the directory `workmux add` uses right now and why.
Resolution order (the same for `workmux add` and the editor):

1. **configured in project**: `worktree_dir` in `.workmux.yaml`
2. **configured globally**: `worktree_dir` in `~/.config/workmux/config.yaml`
3. **detected from existing worktrees**: nothing is configured, but a strict
   majority of the existing worktrees live in one directory other than the
   default (for example `.claude/worktrees`). New worktrees go there too. The
   field is prefilled with that directory (relative to the repo root when
   inside it, `~/...` under home); `s` pins it in the project config
4. **workmux default**: `<project>__worktrees` next to the repository

An empty value removes the project `worktree_dir`. Saving applies to new
worktrees only.

Press `m` to move existing worktrees. Type the new directory (same syntax as
`worktree_dir`) and press Enter: a confirmation lists every
`git worktree move <old> <new>` command. Only worktrees directly in the
current directory are moved; others are listed as untouched. The move is
refused as a whole when a worktree is locked, has an open tmux window or a
running agent, or its target path already exists. `y` runs the moves in the
background (never with `--force`), then saves `worktree_dir`; if a move fails
the rest is skipped and the config is left unchanged.

On the **Tools** page: `a` adds a tool (key, then name, then command),
`Enter` edits the command, `n` the name, `b` the key, `d` deletes, `w` toggles
closing tool windows with `c`. Keys must be one character and unique.

On the **Claude** page each field of the [`claude`](/guide/configuration/#claude-launch-settings)
section is a row: `Enter` edits text (lists comma separated, `extra_args` as
shell words), `Space` cycles model / permission mode / preset and toggles
resume, `d` clears. The bottom line previews the resulting `claude` arguments.

Worktree jumps follow the [`close_on_jump`](/guide/dashboard/configuration/#staying-open-after-a-jump) setting.

## Mouse controls

The dashboard captures mouse input while it is open. Click the **Agents** and
**Worktrees** tabs to switch views, click a table row to select it, and
double-click a row to jump to its agent or worktree. Right-click a row to open
its action menu, then click an action or use `j`/`k` and `Enter`. Click a footer
command to run it. Use the mouse wheel over a table to change the selection
without wrapping, or over the live preview to scroll its output.

In diff view, use the wheel to scroll and click a file in the sidebar to jump to
its diff. Visible diff and patch footer commands are clickable. Mouse capture is
released when the dashboard exits.

## Columns

- **#** (`number`): Quick jump key (1-9)
- **Project** (`project`): Project name (from `__worktrees` path or directory name)
- **Worktree** (`worktree`): Worktree/window name
- **Machine** (`machine`): Remote server name, or `local`, shown once a remote agent is listed
- **Git** (`git`): Diff stats showing branch changes (dim) and uncommitted changes (bright)
- **PR** (`pr`): Pull request number and check status, shown once an agent has one
- **PR Title** (`pr_title`): Pull request title (opt-in)
- **PR Issues** (`pr_issues`): GitHub closing issue references (opt-in)
- **Win** (`window`): Multiplexer window index, blank when the backend does not expose one
- **Status** (`status`): Agent status icon (🤖 working, 💬 waiting, ✅ done, or "stale")
- **Time** (`time`): Time since last status change
- **Title** (`title`): Claude Code session title (auto-generated summary)

Every column of the agents table can be reordered, or left out, with the
[`agent_columns`](/guide/dashboard/configuration/#columns) option, using the names in
parentheses above. The Worktrees tab has a separate
[`worktree_columns`](/guide/dashboard/configuration/#worktree-columns) option for
its columns, including Mux, Age, and Agent.

## Live preview

The bottom half of the dashboard shows a live preview of the selected agent's terminal output. The preview auto-scrolls to show the latest output, but you can scroll through history with `Ctrl+u`/`Ctrl+d`.

## Input mode

Press `i` to enter input mode, which forwards your keystrokes and pasted text directly to the selected agent's pane. This lets you respond to agent prompts without leaving the dashboard. Press `Esc` to exit input mode and return to normal navigation. To use a different exit key and forward `Esc` to the agent, set [`dashboard.input_exit_key`](/guide/dashboard/configuration/#input-mode-exit-key), for example to `Ctrl+q`.

## Sort modes

Press `s` to cycle through sort modes:

- **Priority** (default): Waiting > Done > Working > Stale
- **Project**: Group by project name, then by priority within each project
- **Recency**: Most recently updated first
- **Natural**: Original tmux order (by pane creation)

Your sort preference persists across dashboard sessions. To change the default used when no preference has been persisted yet, set `dashboard.sort_mode` in your config:

```yaml
dashboard:
  sort_mode: recency # priority (default), project, recency, natural
```

## Session filter

Press `F` to toggle the session filter. When active, only agents in the current session are shown. This is useful for session-per-project workflows where each session maps to a repository. You can also start the dashboard with `--session` to default to session filtering. The preference persists across sessions.

## Stale filter

Press `f` to toggle between showing all agents or hiding stale ones. The filter state persists across dashboard sessions within the same tmux server.

## Sweep

Press `R` in either view to open sweep mode, which identifies worktrees ready for cleanup and lets you remove them in bulk. Worktrees are flagged based on these conditions:

- **PR merged**: The associated pull request has been merged
- **PR closed**: The pull request was closed without merging
- **Upstream gone**: The remote branch has been deleted
- **Merged locally**: The branch is fully merged into the main branch with no upstream tracking

The main worktree is never included.

Clean worktrees are pre-selected and can be toggled with `Space`. Dirty worktrees (uncommitted changes) are shown greyed out and cannot be selected. Press `Enter` to remove all selected worktrees, or `Esc` to cancel.
